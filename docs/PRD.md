## 1. 개요

### 1.1 배경 및 목적
Excel 단어장(단어 – 뜻)을 SQLite DB로 옮기고, 이를 기반으로 한 단어 퀴즈를 반복 진행하여 **단어 암기**를 돕는 독립 실행형 웹 프로그램이다. 첫 지원 언어는 **Latin**(뜻은 독일어)이며, English는 향후 지원한다.

### 1.2 목표
| # | 목표 | 성공 기준 |
|---|------|-----------|
| G1 | Excel 단어장을 최소한의 수작업으로 DB에 적재한다 | CLI로 Excel 1개 → 검증 리포트 확인 → DB 반영, 단어 관리 화면에서 확인 가능 |
| G2 | 로그인·서버 설치 없이 더블클릭 한 번으로 퀴즈를 시작한다 | `start.bat` 더블클릭 → 기본 브라우저에 시작 화면 표시 |
| G3 | 틀린 단어를 집중 반복하고, 외운 단어는 pool에서 빼서 암기 효율을 높인다 | 오답 재시험 / 목록 조회, 단어 완료 처리 가능 |
| G4 | 학습 이력을 남겨 진척을 확인한다 | 일자별·세션별·라운드별 결과가 저장됨 |

### 1.3 대상 사용자
- 단일 사용자(본인). 로그인·계정 개념 없음.
- 주 사용 환경은 Windows PC 브라우저, 부가적으로 같은 네트워크 내 모바일 브라우저.

### 1.4 비목표 (Out of Scope)
- 로그인, 다중 사용자, 권한 관리
- 클라우드 배포, 외부 서비스 연동
- 이미지/사진 입력 (입력 소스는 Excel 파일만)
- 앱 화면에서의 단어 추가/삭제 (수정만 지원. 추가는 import CLI로만)
- English 단어장 지원 (향후 업그레이드. 이번 범위에서는 선택 화면에 "준비 중"으로만 표시)
- 발음(TTS), 예문 등 부가 학습 기능 (향후 후보)

## 2. 용어 정의

| 용어 | 정의 |
|------|------|
| 언어 | 단어장의 종류. 현재 Latin, 향후 English. 언어마다 성격이 달라 DB를 따로 둔다 |
| DB | 단어와 학습 기록을 담는 SQLite 파일. 한 언어에 DB가 둘 이상 있을 수 있다 |
| 세션 | 특정 DB를 선택해 시작한 시점부터, 프로그램 종료(콘솔 종료) 또는 DB 전환까지. 한 세션에 하나 이상의 라운드가 있다 |
| 라운드 | 사용자가 Start를 눌러 시작하는 한 번의 출제 묶음. 기본 20문제(설정 변경 가능). 라운드 번호는 **DB별로** 세며 재시작 후에도 이어진다 |
| pool | 현재 라운드에 출제 가능한 단어 집합 (완료 단어와 출제 제외 기간 중인 단어는 빠진다) |
| 뜻 묶음 | Excel의 뜻 열(뜻1~뜻4) 하나. 한 묶음 안에 쉼표로 구분된 동의어가 여러 개 있을 수 있다 |
| Perfect | 모든 뜻 묶음을 맞춘 것 |
| 연속 정답 수 | 연속으로 Perfect를 받은 횟수. 부분 정답이나 오답이면 0으로 리셋 |
| 오답 마크 | 한 번이라도 틀린(Perfect가 아닌) 단어에 붙는 표시 |
| 완료 | 외운 것으로 판단하여 pool에서 제외한 상태 |

## 3. 사용자 시나리오

### 3.1 단어 등록 (Excel → DB)
1. 사용자가 단어장 Excel 파일을 준비한다. 형식은 `data/latin_wortschatz.xlsx`와 같다.

   | 열 | 내용 |
   |----|------|
   | A `단어` | 표제어 전체. 예: `conicere, coniciō, coniēcī, coniectum` (주요 형태·문법 메모 포함, 셀 전체를 하나의 표제어로 취급) |
   | B~E `뜻1`~`뜻4` | 뜻 묶음. 한 셀에 쉼표로 구분된 동의어가 있을 수 있다. 비어 있는 열은 무시 |
   | F `노트` | DB에 저장만 하고 퀴즈에서는 사용하지 않는다 |

2. 별도 CLI 프로그램(`start.bat`과 같은 디렉터리에 위치)으로 import한다. 흐름은 다음과 같다.
   1. CLI를 **검증 모드**로 실행하면 DB는 건드리지 않고 결과 리포트만 **stdout과 별도 파일**에 출력한다.
   2. 사용자가 리포트를 검토하고 문제가 있으면 **Excel 파일을 수정**한다.
   3. 문제가 없으면 **반영 옵션**(`--apply` 등)을 주고 다시 실행하여 DB에 반영한다.
3. 반영 대상은 **기존 DB에 merge** 하거나 **새 DB로 생성** 중에서 선택한다. (Latin Excel 파일이 여러 개일 수 있다.)
4. 사용자는 앱의 단어 관리 화면에서 결과를 확인하고 오타를 수정한다.

> **의도**: 앱은 "DB에 든 단어를 퀴즈로 내는 것"에 집중하고, 데이터 적재는 별도 CLI가 맡는다.

### 3.2 시작 및 DB 선택
1. `start.bat`으로 프로그램을 실행하면 브라우저에 **시작 화면**이 열린다.
2. 사용자가 **언어**(Latin / English)를 고르고, 해당 언어의 **DB를 콤보박스**에서 선택한 뒤 시작한다.
   - English는 "준비 중"으로 표시하고 선택할 수 없다.
3. 선택한 DB가 없으면 **"해당 DB가 없습니다."** Alert를 보여주고 시작 화면으로 돌아간다.
4. 진행 중 DB를 바꾸려면 상단의 DB 전환 기능을 쓴다. **전환하면 현재 세션을 종료하고 새 세션을 시작**한다.

### 3.3 퀴즈 진행
1. 사용자가 출제 방향(**단어→뜻 / 뜻→단어 / Mix**)을 라디오 버튼으로 고르고 **Start** 를 눌러 라운드를 시작한다.
   - **Latin은 `단어→뜻`만 지원**한다. `뜻→단어`와 `Mix` 라디오는 비활성화되고 `단어→뜻`으로 고정된다.
2. pool에서 무작위로 뽑힌 단어가 한 번씩 출제된다. (한 라운드에서 같은 단어는 한 번만 나온다) 표제어는 셀 전체를 **그대로** 보여준다.
3. 사용자가 답을 입력하고 **Enter** 또는 입력창 옆 **Submit** 으로 제출한다.
4. 제출 직후 입력창 **바로 아래 줄에 정답**과 채점 결과가 표시된다.
5. 정답 아래의 **[완료 표시]** 버튼으로 해당 단어를 pool에서 뺄 수 있다.
6. 다음 문제로 넘어가 라운드 마지막 문제까지 반복한다.
7. 라운드가 끝나면 결과(**N문제 중 M개 정답, 정답률 %**)를 보여준다.

### 3.4 오답 복습
- **오답 목록**: 오답 마크된 단어를 표(단어 / 뜻)로 조회한다.
- **오답 재시험**: 오답 마크된 단어만으로 라운드를 구성해 진행한다. 출제 제외 규칙(4.3)은 동일하게 적용된다.

### 3.5 단어 관리
- 단어 목록을 조회하고 단어·뜻을 **수정**한다. (오타 교정 목적)
- **완료** 체크박스로 완료 여부를 확인·변경한다.

### 3.6 설정
- 라운드당 문제 수를 조정한다. (기본 20)

## 4. 기능 요구사항

### 4.1 라운드 구성
| 항목 | 규칙 |
|------|------|
| 문제 수 | 설정값(기본 20). pool이 설정값보다 적으면 남은 단어만으로 짧은 라운드를 진행한다 |
| 출제 방식 | pool에서 무작위 추출, 라운드 내 단어 중복 없음 |
| 방향 | 라운드 시작 시 선택: `단어→뜻` / `뜻→단어` / `Mix` (Mix는 문제마다 방향이 무작위). **Latin은 `단어→뜻`만 활성** |
| 종료 | 마지막 문제 제출 시 종료. 별도의 "라운드 완료 조건"은 없다 |
| 틀린 단어 | 같은 라운드 안에서 재출제하지 않고 다음 라운드로 넘어간다 |
| 종료 화면 | 정답 수 / 문제 수 / 정답률을 표시한다 |
| pool 비었을 때 | "출제 가능한 단어 없음" 안내를 보여준다 |
| 전 단어 완료 | 전 단어가 완료 상태이면 전용 안내 화면을 보여준다 |

### 4.2 채점 규칙
**공통 (정규화)**
- 대소문자를 구분하지 않는다.
- 독일어 표기 변환을 허용한다: `ä = ae`, `ö = oe`, `ü = ue`, `ß = ss`. (정답과 입력 양쪽에 적용)
- 뜻 구분자는 **쉼표만** 사용한다. 스페이스는 구분자가 아니라 뜻의 일부다. (예: `sich setzen`은 하나의 뜻)

**단어→뜻**
| 항목 | 규칙 |
|------|------|
| 입력 방식 | 쉼표로 구분해 여러 뜻을 입력한다. 순서는 무관 |
| 뜻 묶음 매칭 | 각 뜻 묶음(뜻1~뜻4 열)은 **묶음 안의 동의어 중 하나만 맞아도** 충족된 것으로 본다 |
| 괄호 표기 | 정답의 괄호 안 내용은 생략해도 정답으로 인정한다. 예: 정답 `(zusammen)werfen` → `werfen`도 정답 |
| 판정 | 모든 묶음 충족 → **Perfect** / 일부만 충족 → **부분 정답** / 하나도 충족 못함 → **오답** |
| 색 표시 | 정답 줄에서 **충족한 뜻 묶음과 놓친 뜻 묶음을 다른 색으로 구분**해 보여준다 |

채점 예시 (`capere`의 정답: 뜻1 = `fassen, nehmen` / 뜻2 = `erobern`)

| 사용자 입력 | 판정 |
|-------------|------|
| `nehmen, erobern` | Perfect |
| `fassen, erobern` | Perfect |
| `nehmen` | 부분 정답 (1/2) |
| `schicken` | 오답 |

**뜻→단어** (English 지원 시 적용. Latin에서는 사용하지 않음)
- 뜻이 여러 개인 단어는 **뜻을 모두 보여주고** 단어를 입력받는다.
- 같은 뜻을 가진 **다른 단어를 입력해도 정답**으로 인정하고 표시한다.

### 4.3 단어 상태 및 출제 규칙
단어별로 아래 상태를 관리한다. 진행 상태는 **방향별로 나누지 않고 단어 하나에 합쳐** 센다.

| 상태 | 설명 |
|------|------|
| 연속 정답 수 | 연속 Perfect 횟수 |
| 오답 마크 | 한 번 틀리면 마크 |
| 다음 출제 가능 라운드 | 이 라운드 번호 이상부터 pool에 포함 |
| 완료 여부 | 완료 시 pool에서 제외 |

**Perfect / 오답 후 처리** (제출 시점 라운드 = N)

| 결과 | 연속 정답 수 | 다음 출제 |
|------|--------------|-----------|
| 오답 또는 부분 정답 | 0으로 리셋 | 오답 마크. 다음 라운드(N+1)부터 출제 가능 |
| Perfect 1회째 | 1 | N+1은 건너뛰고 **N+2**부터 출제 가능 |
| Perfect 2회째 | 2 | **N+3**부터 출제 가능 |
| Perfect 3회째 이상 | 3+ | "해당 단어에 완료 표시를 할까요?" 확인창. **Yes** → 완료(pool 제외) / **No** → 2회째와 동일하게 처리 |

- 3회 이상 연속 Perfect이면 **매번** 완료 여부를 묻는다.
- 완료 처리는 정답 아래 **[완료 표시]** 버튼으로도 할 수 있다 (4.5).

### 4.4 오답 기능
- **오답 목록**: 오답 마크된 단어를 (단어 / 뜻) 표로 조회한다. **완료된 단어는 제외**한다.
- **오답 재시험**: 오답 마크된 단어만으로 라운드를 구성한다. 4.3의 출제 제외 규칙을 따르며, 방향 선택도 일반 라운드와 같이 제공한다 (Latin은 `단어→뜻` 고정).
- **오답 마크 해제**: 단어가 **완료 처리될 때** 해제한다. 그 전에는 유지한다.

### 4.5 완료 표시
- 정답 확인 후 정답 아래에 **[완료 표시]** 버튼을 둔다.
  - Perfect, 부분 정답: **활성화**
  - 오답: **비활성화**
- 버튼을 누르면 해당 단어는 pool에서 제외된다.
- 단어 관리 화면의 **완료 체크박스**로도 변경할 수 있다 (4.6).

### 4.6 단어 관리
- 단어 목록 조회, 단어·뜻 수정. 저장 시 이후 퀴즈에 즉시 반영된다.
- **완료** 체크박스 열: 완료된 단어는 체크되어 있고, 체크를 해제하면 다시 pool에 복귀한다.
- 단어 추가/삭제는 앱에서 지원하지 않는다 (추가는 import CLI로만).

### 4.7 설정
- 라운드당 문제 수 (기본 20)
- 설정값은 SQLite에 저장되어 재시작 후에도 유지된다.

### 4.8 하단 상태 바 (항상 표시)
- 현재 DB에 저장된 전체 단어 수
- 현재 세션의 **테스트한 단어 수 / 맞춘 개수**

### 4.9 언어 및 DB 관리
- 언어별로 DB를 **별도 SQLite 파일**로 둔다 (예: `latin.db`, 향후 `english.db`). 한 언어에 여러 DB를 둘 수 있다.
- 시작 화면에서 언어를 고르고, 그 언어의 DB를 **콤보박스**로 선택한다.
- 라운드 번호, 진행 상태, 설정, 이력은 **DB 단위로** 독립 관리한다.
- 선택한 DB가 없으면 "해당 DB가 없습니다." Alert 후 시작 화면으로 돌아간다.
- 진행 중 DB를 전환하면 현재 세션을 종료(종료 시각 기록)하고 새 세션을 시작한다.

### 4.10 Import CLI
`start.bat`과 별개인 간단한 CLI 프로그램이다. 웹 서버와 같은 디렉터리에 두고 함께 배포한다.

| 항목 | 규칙 |
|------|------|
| 입력 | Excel(.xlsx) 파일 경로. 형식은 3.1 |
| 검증 모드 (기본) | DB를 변경하지 않고 리포트만 출력한다 |
| 반영 모드 | 별도 옵션(`--apply` 등)을 준 경우에만 DB를 변경한다 |
| 리포트 | **stdout과 별도 파일** 양쪽에 저장. 추가 / 갱신 / 건너뜀 / 오류 건수와 항목별 상세 |
| 반영 대상 | **기존 DB에 merge** 또는 **새 DB로 생성** 중 선택 |
| 중복 처리 (merge) | 표제어(단어 셀 전체)가 같으면 동일 단어로 본다. 이미 있는 단어는 **뜻·노트만 갱신하고 진행 상태는 보존**, 새 단어는 추가, Excel에서 사라진 단어는 **삭제하지 않고 리포트에 표시만** 한다 |
| 인코딩 | UTF-8. 장음 기호(`ā ē ī ō ū`)와 움라우트가 콘솔과 DB에서 깨지지 않아야 한다 |
| 세부 | 헤더 행 처리, 빈 뜻 열, 파일 경로 인자 등은 기술 스펙에서 정한다 |

### 4.11 저장 데이터 (SQLite, DB별)
| 구분 | 내용 |
|------|------|
| 단어 정보 | 표제어(셀 전체), 뜻 묶음(열별 동의어 목록), 노트, 등록 시점 등 |
| 단어별 진행 상태 | 연속 정답 수, 오답 마크, 다음 출제 가능 라운드, 완료 여부 |
| 설정 | 라운드당 문제 수 등 |
| 접속 로그 | 세션 시작 및 종료 시각 |
| 라운드 이력 | 라운드 번호 (재시작 후에도 이어짐), 소속 세션, 방향, 시작·종료 시각, 정답률 |
| 테스트 결과 | 일자별 / 세션별 / 라운드별 결과 (출제 단어, 방향, 제출 답, 채점 결과) |

- 로그인은 없다.
- 정확한 스키마는 기술 스펙에서 정한다.

## 6. 배포 및 실행 요구사항

| 항목 | 요구사항 |
|------|----------|
| 설치 위치 | `C:\WordQuiz` (없으면 생성) |
| 사전 조건 | Windows PC에 Node 설치되어 있음 (별도 설치 불필요) |
| 실행 방법 | `C:\WordQuiz\start.bat` 더블클릭 |
| 접속 주소 | `http://localhost:35000` — 기본 브라우저가 자동으로 열림 |
| Import CLI | 같은 디렉터리에 포함. `start.bat`과는 별도로 실행 |
| 의존성 패키지 | 웹 서버와 import CLI가 쓰는 `node_modules` 를 모두 포함하여 **한두 개 파일로 압축**하여 배포 |
| 개발/실행 환경 | 개발은 WSL, 실행은 Windows |
| 종료 | **콘솔을 종료할 때** 종료 시각이 접속 로그에 기록된다 |
| 문자 인코딩 | `start.bat`과 CLI 모두 UTF-8(`chcp 65001` 등)로 실행 |

- **기술 스펙에서 검토할 위험**: 개발(WSL/Linux)과 실행(Windows)의 OS가 달라 네이티브 모듈(예: `better-sqlite3`)은 그대로 배포할 수 없다. Node 내장 `node:sqlite`, 순수 JS/WASM 계열(`sql.js`), 또는 Windows용 별도 빌드 중에서 선택해야 한다. xlsx 파서는 순수 JS 라이브러리를 사용한다.

## 7. 비기능 요구사항
- **간편성**: 설치 과정 없이 더블클릭으로 시작한다.
- **로컬 전용**: 데이터는 로컬 SQLite 파일에만 저장되며 외부로 전송되지 않는다.
- **반응형**: 데스크톱과 모바일 화면 모두 지원한다.
- **데이터 보존**: 앱을 재시작해도 단어, 진행 상태, 설정, 이력이 유지된다.
- **언어 확장성**: English 등 새 언어를 추가해도 기존 Latin DB와 로직에 영향이 없어야 한다. (DB 분리, 언어별 방향 옵션)

## 8. 결정 사항 및 미결 사항

### 8.1 결정 로그
| # | 주제 | 결정 |
|---|------|------|
| D1 | 부분 정답 | 오답으로 마크. 맞춘 부분은 다른 색으로 표시 |

| D3 | 세션 | 특정 DB 시작~프로그램 종료 또는 DB 전환. 세션 내 라운드 1개 이상 |
| D4 | 출제 제외 | 4.3 표 (연속 Perfect 기준, 리셋 규칙 포함). Perfect 2회째는 N+3 |
| D5 | 단어 추가/삭제 | 앱 화면에서는 미지원 (수정만). 추가는 import CLI로만 |
| D6 | 종료 감지 | 콘솔 종료 시 기록 |
| D7 | 모바일 | 같은 네트워크 내 PC 서버 접속 |
| D8 | 입력 소스 | Excel 파일 import만 고려. 사진/OCR은 범위 밖 |
| D9 | 뜻 구분자 | 쉼표만 구분자. 스페이스는 뜻의 일부 |
| D10 | 뜻→단어 | 뜻 전부 표시, 동의어 정답 인정, 진행 상태는 단어 단위 통합 (English 지원 시 적용) |
| D11 | 오답 재시험 | 출제 제외 규칙 동일 적용, 방향 선택 제공 (Latin은 단어→뜻 고정) |
| D12 | pool 고갈 | 안내 문구 표시 + 전 단어 완료 화면 |
| D13 | 완료 표시 | 정답 아래 버튼(오답 시 비활성) + 단어 관리 체크박스 |
| D14 | 라운드 크기 | 기본 20, 설정 메뉴에서 조정 |
| D15 | 오답 마크 | 완료 처리 시 해제. 완료된 단어는 오답 목록에서 제외 |
| D16 | pool 부족 | 설정값보다 적으면 남은 단어만으로 짧은 라운드 진행 |
| D17 | 동의어 정답 (뜻→단어) | 출제 단어의 진행 상태에만 반영하고 "다른 정답 단어: X"를 표시. Latin에서는 해당 없음 |
| D18 | 뜻 묶음 단위 | 뜻 열(뜻1~4) 하나가 묶음. 묶음 안의 쉼표 항목은 동의어(하나만 맞아도 충족). 묶음 단위로 Perfect/부분 정답 판정 |
| D19 | 괄호 표기 | 정답의 괄호 안 내용은 생략해도 정답 인정 |
| D20 | 독일어 정규화 | 대소문자 무시, `ä=ae` `ö=oe` `ü=ue` `ß=ss` 허용 |
| D21 | 표제어·노트 | 단어 셀 전체를 표제어로 저장하고 퀴즈 화면에 그대로 표시. 노트는 저장만 하고 퀴즈에서 미사용 |
| D22 | 언어/DB 분리 | 언어별 별도 SQLite 파일, 한 언어에 여러 DB 가능. 라운드 번호 등 모든 상태는 DB별 |
| D23 | DB 선택 | 시작 화면에서 언어 선택 후 DB 콤보박스로 선택. DB 없으면 "해당 DB가 없습니다." Alert 후 시작 화면 복귀 |
| D24 | DB 전환 | 진행 중 전환하면 세션을 종료하고 새 세션으로 시작 |
| D25 | Latin 방향 | 단어→뜻만 지원. 뜻→단어, Mix 라디오는 비활성 |
| D26 | English | 이번 범위 밖. 시작 화면에 "준비 중"으로 표시(선택 불가) |
| D27 | Import CLI | 웹 앱과 별도 CLI. 검증 모드(리포트만, stdout+파일) 확인 후 반영 옵션으로 DB 갱신 |
| D28 | Import 대상 | 기존 DB에 merge 또는 새 DB 생성 선택 |
| D29 | 배포 | import CLI도 같은 디렉터리에 두고 의존성 압축 파일에 포함 |
| D30 | 인코딩 | `start.bat`과 CLI 모두 UTF-8 (장음 기호 대응) |
| D31 | merge 중복 처리 | 표제어가 같으면 뜻·노트만 갱신하고 진행 상태 보존, 새 단어는 추가, 사라진 단어는 삭제하지 않고 리포트에만 표시 |
| D32 | 뜻 묶음 매칭 | 정답 묶음에 없는 입력 항목은 감점하지 않음. 각 묶음의 충족 여부만 본다 (예: `fassen, nehmen, erobern`도 Perfect) |
