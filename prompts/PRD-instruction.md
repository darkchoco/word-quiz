# 목표
사진으로 제공되는 입력 정보를 읽어서 DB에 저장 후 독립실행 웹 프로그램을 통해 단어 퀴즈를 진행, 단어의 암기를 도모한다.

# Tech Stack
- TypeScript + React
- Material UI
- SQLite
- Node (개발은 WSL 환경에서, 실행은 Windows 환경에서)

# Conventions
- 커밋 메시지는 Conventional Commits 형식. `feat: Create...` 식으로. `feat, fix, docs, style, refactor, test, chore` 로 구분.
- 커밋 메시지 마지막에 'Co-Authored-By...'는 절대 추가하지 말 것
- 커밋 실행 전 반드시 커밋 메시지를 먼저 보여주고 사용자 확인을 받을 것

# Requirements
- 구성
    - 입력은 사진 데이터에서 가져온다.
        - 지금은 사진 내 검은 박스로 표시된 부분에 들어있는 정보를 가져오지만 향후에는 달라질 수 있다.
            - 이 부분은 프로그램으로 어려울 수 있다. 차라리 claude 프로젝트를 만들어서 SQLite DB를 같이 올려놓은 다음, 입력 자료를 받을 때마다 claude가 변환하여 DB에 저장하는 식으로 가야할 수도 있다.
        - 기본적으로 사진 데이터의 내용은 단어 테이블이며 왼쪽 칼럼은 외울 단어, 오른쪽 칼럼은 그 단어의 뜻으로 구성되어 있다.
    - SQLite에 저장된 데이터는 다음과 같다.
        - 단어 정보
        - 접속 로그 (프로그램 시작 및 종료)
        - 일자별/세션별 테스트 결과
    - 로그인은 필요없다.
    - 배포는 C 드라이브 밑에 WordQuiz 라는 디렉토리에 한다. (없으면 생성)
        - 윈도우 PC는 node가 이미 설치되어 있다고 가정한다.
        - 해당 디렉토리 내 start.bat 를 더블클릭 하면 디폴트 브라우저에서 http://localhost:35000 으로 실행된다.
        - node_modules 은 한두개 파일로 압축한다.
    - 화면에 나타나는 'Start' 버튼을 누르면 외울 단어 pool 에서 임의의 단어가 선택되어 보여진다. 그 단어의 뜻을 입력하면 맞는지 비교한다. 단어의 입력은 엔터키, 또는 입력항목 옆에 있는 'Submit'을 누른다. 그 직후 바로 아래 줄에 정답을 보여준다.
        - 대소문자 구분은 하지 않는다.
        - 뜻이 여러 개일 경우 그 순서는 중요하지 않다. 이 경우 각 단어는 스페이스나 쉼표로 구분될 수 있다. 다 맞추면 perfect, 일부만 맞출 경우 일부만 맞는 것으로 한다.
    - 모든 단어를 다 맞추면 완료 정보를 보여준다.
    - 틀린 단어만 따로 모아서 테스트 할 수 있다.
    - 틀린 단어만 따로 모아서 테이블 형태로 볼 수도 있다.
    - 입력한 단어의 수정이 필요할 수 있기 때문에 수정하는 메뉴도 필요하다.
    - 화면 하단에는 아래 정보를 보여준다.
        - 전체 저장된 단어 수
        - 프로그램 시작 후 테스트 한 단어수 / 맞춘 갯수
- 노트
    - 모바일에서도 실행할 경우를 고려한다.
    - 프로그램 구현 전 UI 에 대한 컨펌을 반드시 받고 진행한다.

# Workflow Rules
- 코드 변경 후 반드시 typecheck 실행
- 전체 테스트 대신 단일 테스트 선호
- 구현 전 plan mode로 영향 파일 먼저 파악할 것
